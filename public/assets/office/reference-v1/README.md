# Reference Office V1

Generated with OpenAI image generation from the user-provided office design.
The room, blank wall whiteboard, conference furniture and desk accessories are
separate layers. Characters and workstation animations use the existing packs.
Board content is rendered dynamically from fixed structured task data;
there are no baked text, diagrams or charts in the frame image.

- `conference-table.png`: meeting table and chairs; runtime footprint is 8 x 3 cells.
- `desk-accessories.png`: plants, mug and books; cropped into separate sprites
  whose visible bases attach to the workstation's measured tabletop surface.
- `room-whiteboard-v3.png`: active background with a conventional wall-mounted
  whiteboard, small corner radii, a thin gray frame and a subtle wall shadow.
  The whiteboard is generated in the room's camera plane, not pasted on top.

WebP alternatives are built by `scripts/build-office-assets.mjs`.

Assembly: `referenceOfficeScenePack` and `createReferenceOfficePresentation()`
are exported by `@pixoffice/scene-office`. The complete office example selects
this layout; the original `officeScenePack` remains available to consumers.
The logical map is 22 x 17 integer cells, with a 1100 x 850 presentation plane.
Workstations and character height share a 1.5x scale around the seat anchor,
including keyboard contact surfaces. Custom current-format saved maps keep their geometry;
retired save formats are not migrated.
Names follow characters. Task cards attach to the right-edge midpoint of their home
monitor using the same drawing geometry as the computer sprite. They remain at
the workstation when a character leaves. Titles, subtitles and known percentages
come from task data; received progress changes ease over 280 ms without changing
business state. The card's left-center pointer targets the monitor.
Only the card surface uses 50% opacity; text and progress remain opaque. A card
folds into one task-title row when a character enters its full visual area, then
restores after 180 ms clear. Hovering or selecting intentionally opens details.
Occlusion tests retain the full card area while folded to avoid flicker.

The wall board defaults to a fixed two-column `state.taskBoard` presentation:
status and task summary on the left, up to three numbered progress rows on the
right, plus a note and an optional HTTP(S) project link. The office example
derives the content from its current team's task data. Missing progress is
shown as unknown, not zero. This is scene-local presentation data, not a new
transport protocol. Lucide icons are generated by
`scripts/assets/build-whiteboard-icons.mjs` under their ISC license, included in
`public/THIRD_PARTY_NOTICES.txt`.

The in-scene board uses the same 778 x 314 desktop content surface as the
expanded reader, with a 22 px preview type scale. Only the complete
surface is scaled to the board face; typography and columns are never squeezed
independently. The preview surface is transparent: only dynamic content is drawn
inside the wall-mounted whiteboard. Its physical frame, material and wall shadow
are never covered with another frame or an opaque content panel.
In-scene progress rows also use a transparent, shadow-free surface so the
whiteboard material remains visible. The expanded reader retains its paper
surface; both use the same layout and task data.
Unused room variants and isolated-frame experiments have been removed.
The current hanging-whiteboard prompt is in `whiteboard-v3-prompts.md`.

The wall board accepts only the fixed `state.taskBoard` structure. It has no
Markdown, HTML or legacy text fallback.
