# 整数格与家具互动

## 唯一空间单位

- `World.unit = "cell"`、`gridSize = 1`。人物、家具、路径、锚点、地面边界和地图协议只接受整数。
- 原点在左上角，x 向右、y 向下。`position: {x: 6, y: 4}` 表示第 6 列、第 4 行的格子，不是像素坐标。
- 人物占 1×1 格。当前工位占 2×2 格，白板占 2×1 格；新家具可声明其他整数尺寸。
- `footprint` 为相对原点的半开区间：`left <= x < right`、`top <= y < bottom`。仅按底部占地计算，不以图片顶部、人物头发或白板面板大小碰撞。
- 普通行走不能进入家具任何占地格。相邻家具之间留出 1 格就可单人通行，留出 2 格更利于双向交通。
- 不再存在“家具一格 = 五个寻路小格”的换算。

渲染层仍需要像素。`gridProjection.ts` 把格子换成画面位置，在相邻两格之间按时间插值，并校正现有桌椅贴图的对齐位置。运行时的 `actor.position` 不随插值变成小数；它只在完成一步时切换到下一格。`step.from/to` 也是整数，`elapsedMs/durationMs` 是时间而不是空间坐标。

当前桌椅的入座只校准最后的地面站位：人物正常走到与椅子对齐的位置，再原地播放坐下；离座反向播放。站姿脚底与坐姿锚点分开，不能把行走路径抬到桌沿。主页面按对齐后的实际距离计算每步时长，使速度与普通地面行走一致，不额外放慢入口，也不在坐下时增加侧移。内核通过可选的 `seatStepDuration` 接收时长，仍只保存整数格。画面朝向取当前动画段；只有已经进入座位位置时，椅背才遮挡人物下半身。

## 家具声明

模板是数据，行为由统一控制器执行。以下是一个 1×1 饮水机的逻辑示例，不代表当前已提供饮水动画素材：

```ts
{
  id: 'office.dispenser',
  name: '饮水机',
  view: 'dispenser',
  footprint: { left: 0, top: 0, right: 1, bottom: 1 },
  anchors: { front: { x: 0, y: 1 } },
  resources: { tap: 1 },
  interactions: {
    drink: {
      name: '接水',
      anchor: 'front',
      approaches: ['front'],
      cells: [],
      posture: 'standing',
      facing: 'back',
      resource: 'tap'
    }
  }
}
```

| 字段 | 含义 |
| --- | --- |
| `anchor` | 实际使用格，引用模板锚点；可以在家具外，也可在内部 |
| `approaches` | 一个或多个入口格，必须是家具外的合法地面 |
| `cells` | 本次交互允许进入的家具内部格；不是全局开放通行 |
| `posture / facing` | 到位后的站姿或坐姿及朝向 |
| `requiresHome` | 仅允许绑定此工位的人使用，默认工位开启 |
| `resource` | 共用的独占资源；省略时使用交互 ID，不同操作可共用同一资源 |

以当前工位为例，内部下排两格允许主人入座，上排桌体仍然禁止进入。入座和离座只走左、右入口，比较完整路线后就近选择；椅背后方不能作为入座捷径，不可达入口自动跳过。两侧都不可达时明确失败，不穿过椅背。后方锚点保留给普通移动，但是否可交谈还必须通过人物动作契约，不能借用主人的内部通道。

## 动作契约

这是代码和素材配置的硬约束，不依赖 AI 提示词。`packages/scene-office/src/core/poseSupport.ts` 保留办公室默认姿态映射，装配层优先使用已加载 VisualAssetManifest 的真实能力；标准 `office` 帧素材包必须提供背向坐姿及左、右坐姿转头，打包和加载时都会验证。无渲染宿主可通过 `supportsPose` 注入自己的能力表，运行时内核不依赖 Pixi。

活动阶段的 `poses` 既是到位后的目标姿态，也是该阶段移动的站位条件。例如工位拜访在移动阶段声明访客站立面向主人、主人坐着面向访客。寻路根据候选点的实际坐标计算双方朝向，排除不能播放对应动作的位置，再在合法位置中选最近的可通行路线；地图修改锚点也不能绕过校验。被堵重新寻路时保留同一条件。

执行顺序为 `校验目标动作 → 移动 → 校验实际到位姿态 → 转向 → 说话 → 回复 → 恢复`。同阶段的姿态全部校验成功后才一起应用并开始说话。没有支持的站位时返回 `UNSUPPORTED_POSE`；支持的站位都不可达时返回 `NO_ROUTE`，不使用后方位置或背向坐姿伪装交谈。取消和结束时清除讲话并恢复主人的背向坐姿。

新增人物要满足标准动作；新增家具和能力插件必须声明实际需要的姿态。若新增可向后转头的坐姿素材，可由能力适配器开放对应朝向，现有寻路与交谈不需要为人物身份写特殊分支。未注入能力适配器的通用 `OfficeRuntime` 保持宿主兼容，不提供素材保障；本项目的 `createOfficeRuntime` 默认启用标准办公室契约。此约束不改变碰撞、格子尺寸、桌椅位置或现有动画帧。

## 执行流程

`提交 → 排队/预约 → 选最近可用入口 → 逐格靠近 → 预约局部通道 → 到使用格 → 保持动作 → 离开 → 释放`

1. 人物身体和家具资源原子预约，不会拿到一半资源再等待。冲突命令有界排队。
2. 比较完整的出入口路径，优先可通行路线，再比较距离；不会仅因为左入口写在数组前面就绕到左边。
3. 普通移动每步预约起点和终点；家具过渡预约完整局部通道。人物不能重叠或迎面交换格子。
4. 临时被堵先等待，再重新寻路；相向人员使用稳定顺序确定一方保持路线，另一方绕行，避免同步左右摇摆。持续堵塞会明确失败，不瞬移穿人。
5. 取消普通移动会走完当前已承诺的一格，然后停下。取消入座/离座会沿保留的局部通道恢复安全姿态。取消家具使用会先退出使用位置，再释放资源；出口持续被堵时保留占用，等待通路恢复。
6. `activity.ended` 表示任务已结束；若仍在安全收尾，资源会保留到 `activity.settled`。这期间禁止编辑家具。

当前界面可在左侧选择人物和“家具互动”，点击“使用家具”。已接入本人座位和查看白板；白板会议依次进入后排、前排，反序离开，避免先到的人封住内部站位。

## 外部调用

```json
{
  "protocolVersion": "2.0",
  "sceneId": "office-1",
  "commandId": "use-board-001",
  "type": "activity.start",
  "capability": "furniture.use",
  "participants": [{ "entityId": "marvis", "role": "user" }],
  "params": {
    "objectId": "whiteboard-1",
    "interactionId": "write",
    "durationMs": 4000
  }
}
```

当前白板 `write` 交互实际表现为到白板前查看、停留并返回，不伪造尚不存在的书写动画。内容更新仍通过 `object.state.set`。后续新增饮水机、跑步机等，只需注册整数格模板和对应视图；专属动作、业务效果和多人使用规则由能力插件扩展。

## 存档与兼容

- 命令协议 `2.0`，地图文档及检查点 `version: 2`。新命令不接受 v1 连续单位或小数坐标。
- 浏览器仍使用原存储键以找到旧存档。已知 960×640 v1 场景会换算到最近可摆放整数格，先完整备份原存档，再写入新版本。
- 保留人物身份、绑定、家具 ID、物品内容、展示状态和命令历史；中断任务不重放。
- 无合法布局、未知实体/模板或备份失败时不覆盖原数据，显示错误；符合安全条件时可手动备份并恢复默认布局。
- 旧地图 JSON 不直接导入；先在原存档迁移后重新导出 v2。未知插件版本仍需专门的迁移器。

这是单层小型场景的网格调度，不承诺任意拥挤布局均能自动脱困。家具布局应保留可达入口和足够通道；旋转家具、多层地图、推车和多人共同搬运尚未实现。
