# 人物素材准入流程

这是新增、修改人物的正式入口。提示词帮助生成，代码负责拦截可测量错误，视觉验收负责确认形象、动作和家具接触是否自然。通过自动检查不等于美术合格。

## 流程与边界

```text
锁定正/侧/背母版 → 定义动作模板 → 生成候选图 → 整图统一配准
  → 自动审计 → 隔离预览与人工验收 → 版本绑定的发布 → 正式办公室
```

- 本轮只增加流程和检查，不修改现有人物图片。旧版身体抖动仍待后续修图。
- 六个现有人物的原始内容指纹记录在 `scripts/characters/legacy-baseline.json`，状态为 `legacy-frozen`，不是验收合格。仅完全未变的旧内容可继续构建；新增人物、改变任一已引用图片或配置不能借用旧人物 ID 豁免。
- 不要更新历史白名单来接受新素材，不要放宽公差隐藏缺陷。素材修复后应通过新流程转为 `approved`。
- 正式 CLI、开发启动、测试、生产构建都会执行准入。底层 `buildCharacter()` 保留无准入的打包能力，仅供隔离预览和打包器测试；不是发布入口。
- 这是仓库协作规则，不是对恶意修改代码者的安全沙箱。验收记录不带数字签名，维护者仍需通过代码审查确认标注与证据真实。

## 资源与职责

| 文件 | 用途 |
| --- | --- |
| `character.json` | 动作、方向、帧顺序、时长、嘴型挂点 |
| `standard.json` | 每个人自己的三视图头部母版数据、头部区域、足底与尺寸公差 |
| `quality.json` | 母版图片哈希、逐帧导入记录、动作模板、允许变化区域及连续性上限 |
| `review.json` | 人工验收人、时间、检查项、证据文件哈希和完整素材版本指纹 |
| `evidence/` | 实际验收截图或 GIF，跟随该版本保存 |

标注属于制作期数据，不打入运行时图集，不增加每帧计算。原图、生成提示、生成结果标识及原图裁切记录仍应另存在版本化 `art/characters/<制作版本>/`。

## 硬性检查

| 范畴 | 拦截条件 |
| --- | --- |
| 画布与比例 | 不是 256×384 透明画布、锚点不是 (128,344)、参考高度不是 280、显示高度不是 84 |
| 身份母版 | 缺正/右侧/背站姿、母版图片哈希不符、母版实际头部测量与标注不符 |
| 动作覆盖 | 任一启用的身体动作缺模板、头部/足底规范；别名不能把身体伪装成部件 |
| 配准 | 缺导入记录；同一动作不同倍率；静止/工作/说话身体逐帧平移 |
| 工作帧 | 两侧手指小区域之外有任何可见 RGBA 差异；任一手指区域始终不动；未循环 |
| 静止/说话 | 静止身体像素变化；说话身体在标记口型区域之外变化 |
| 步态 | 当前室内模板不是四张独立的接触/经过/反向接触/经过帧，或未循环 |
| 连续性 | 相邻帧以及循环末帧到首帧的头部位置、面积或轮廓变化超过模板限值 |
| 发布 | 缺视觉验收、检查项未全完成、证据哈希不符、素材改过但沿用旧验收 |

工作帧以完整人物 PNG 播放。允许修改两只手指所在的小区域，但头发、头、衣服和躯干必须保留相同像素；不通过拼接手臂或运行时抖动补救。区域最多两个，总面积不超过画布的 8%，左区不得跨入 x≥108、右区不得跨入 x<148 的身体中央范围。区域位置必须按实际手指标注，不能照抄例子或把整个人物框进去。

全身动作比较实际像素与人工头部标注：默认相邻头部位移 4px、相邻头部面积差 3.5%、轮廓变化 35%；配置硬上限分别为 6px、3.5%、45%。坐起动作允许头部正常升降，但仍限制横移与头部面积。尺寸规范默认头宽 ±14px、头高 ±16px、中心与足底 ±2px、头部面积 ±3.5%。已有长发动作单帧头宽例外由尺寸规范保留，不能套给所有动作。

数值检查不能判断左右腿是否真的交替、五官是否画错、手是否压到键盘上。`phases` 和配准参数也是制作记录，不是自动识别结果。以上项目必须在视觉验收中逐一确认。

## 新增或修改一个人物

### 1. 准备暂存包

把完整候选包放到 `.character-staging/<版本>/<人物ID>/`，不能直接改 `art/characters/packs/`。修改已有角色时先复制到暂存目录，再换图片和配置；未改的历史动作可以从候选包中移除，但必须保留办公室必需动作。不要把历史试验动作全部带入新的正式包。

先确定三视图母版，再制作动作。同一个动作从同一母版出发，用同一导入倍率；工作动作优先保留中性姿态的身体像素，只生成局部手指编辑。生成不稳定时退回修图，不能给每帧单独凑尺寸。

```sh
npm run characters:draft -- --pack .character-staging/v1/new-person
```

命令只创建 `quality.json` 草稿：自动登记动作与母版哈希，配准记录和工作区域故意留空，不伪造数据。已有文件不覆盖。补充实际 `registrations`，并核实每个动作模板、参考帧和 `standard.json`。

工作动作局部示意（不是可直接套用的坐标）：

```json
{
  "registrations": {
    "work/001.png": { "scale": 0.62, "x": 28, "y": 52 },
    "work/002.png": { "scale": 0.62, "x": 28, "y": 52 }
  },
  "actions": {
    "work.quiet-back": {
      "template": "work",
      "reference": "work/001.png",
      "changes": [
        { "x": 25, "y": 215, "width": 55, "height": 55 },
        { "x": 174, "y": 215, "width": 55, "height": 55 }
      ]
    }
  }
}
```

`scale/x/y` 记录原始裁切图到最终画布的真实等比变换；已经在标准画布上直接绘制的帧才可填写 `1/0/0`。不能为通过检查而伪造一致参数。

### 2. 自动审计

```sh
npm run characters:audit -- --pack .character-staging/v1/new-person
```

失败返回非零退出码，输出动作、文件和原因；不改图片。可加 `--report <新JSON路径>` 保存报告，已有报告不覆盖。缺规则时只报告缺失，不冒充已经检查过身体像素。旧人物直接审计可能失败，这是预期，不是修图已完成。

### 3. 隔离预览

```sh
npm run characters:preview -- --pack .character-staging/v1/new-person
npm run dev:vite
```

打开命令返回的 `previewPath`，使用终端实际显示的 Vite 地址。预览图集写入 `.character-preview/<素材指纹>/`，不写正式注册表、不进入 `dist`、不修改办公室存档，也不连接外部动作网关。候选即使未验收也能预览，但基础格式与尺寸规范仍必须通过。

独立预览页沿用正式 OfficeScene、真实桌椅和播放器，六个位置暂时显示同一个候选外观，便于观察不同位置和交谈方向。可用“动作逐帧”“走动与交谈”“重置工位”；关闭页签即结束这套临时场景。它始终标记“未验收”，没有自动批准按钮。

人工必查：

1. `identity`：三视图、站立/坐姿头部与服装一致，无残边、武器或不符合目标风格的构件。
2. `motion`：左右腿交替；工作身体固定；逐帧与循环末首无闪动；闭嘴行走；说话只在应该说话时发生。
3. `desk-contact`：真实工位上手指在键盘区域，不悬空、不落在桌下，坐起没有穿模或突变。
4. `labels`：办公室姓名、状态气泡位置稳定，不随工作帧包围盒抖动。
5. `scene`：真实场景正常速度的走停、入座、工作、起身、双向拜访及打断恢复完整验收。

### 4. 留下版本绑定的视觉记录

```sh
npm run characters:review -- --pack .character-staging/v1/new-person
```

只有自动审计通过才创建 `review.pending.json`。默认所有检查项都是 `false`。完成上述检查后填写真实验收人、ISO 时间、备注和截图/GIF证据，把已完成项改为 `true`，最后将它改名为 `review.json`。证据必须位于候选包内，填写对应文件 SHA-256；可用 `shasum -a 256 <文件>` 获取。不要把未看过的项目打勾。

其中 `digest` 绑定该人物配置、所有启用图片、尺寸规则和质量规则。改素材、帧顺序、时长、标注或公差都会让旧验收失效；只改证据文件也会被证据哈希检测到。

### 5. 正式发布

```sh
npm run characters:publish -- --pack .character-staging/v1/new-person
npm run characters:check
npm test
```

发布前再完整校验一次，复制后再次检查内容指纹，随后备份旧包至 `.character-backups/`，安装新包并重建图集。构建失败恢复原包，旧注册表不被覆盖。保留备份直到确认新版本正常；脚本不自动删除历史备份。

旧的一次性导入脚本保留用于查阅制作算法，但直接写正式包的入口已禁用；带暂存能力的旧脚本仍可生成候选，`--publish` 被拒绝。不要再照历史素材 README 的旧发布命令操作。

新增外观不会自动新增业务员工或工位。正式发布后，在场景 actor 的 `templateId` 选择该资源包即可。

## 扩展新动作

先定义一个动作模板，明确方向、姿态、阶段顺序、循环规则、可变区域、尺寸与接触点；在一个候选人物验证后再推广。现有 `still/work/walk/transition/gesture/speech/part` 模板有意保持收敛。超出模板的真实需求应新增有测试的规则版本，而不是把新动作标成 `part` 跳过校验。

这套流程降低重复犯错的概率，不能保证图像生成一次成功，也不能自动证明动作好看。
