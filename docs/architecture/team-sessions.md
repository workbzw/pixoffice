# 团队会话与视图生命周期

每个团队由 `OfficeTeamSession` 持有独立的数据源、场景运行时和最新业务快照。应用启动所有团队会话；切换团队只切换可见画布，不取消其他团队的数据订阅，也不从切换时的存档恢复。

```text
业务推送 / 可选宿主数据源  -> 团队会话 -> 最新业务快照 -> 当前可见 UI
场景命令 / SSE 投递       -> 对应团队运行时 -> 行为执行结果
动画时钟                  -> 已接收行为的移动、动作阶段和帧播放
```

- 任务状态来自业务数据源。走路、对话或动画完成不会自动把业务任务标为完成。
- 服务器办公室使用 `OfficeIntegrationSession` 和 `PushOfficeDataSource` 接收推送，不轮询业务后台。内置旧业务 HTTP 适配器已删除。远程完整快照按每个办公室的递增 `seq` 过滤乱序，不能使用旧快照覆盖新状态。
- `DashboardSceneBridge` 随团队会话存在，避免切换视图时重新播放历史交接事件；最终快照里已完成或已改派的任务不会补播旧交接。仅缓存触发行为的交接事件 ID，最多保留最近 1024 个；临时动画不保证无限期去重。
- 真实数据源通过 `snapshot.whiteboard` 控制固定格式白板，并与任务共用 `seq`、缓存和重连恢复；内部物品版本由前端管理。业务源不通过自动摘要覆盖白板。本地示例仍可生成自己的摘要。
- 团队订阅或通道初始化失败只更新该团队的错误状态，撤销已建立的订阅，其他团队继续启动。失败会话可再次 `start()`；会话集合再次更新时也会重试未启动的会话。清理回调报错不会阻止其他连接释放。
- 隐藏团队继续消费数据与执行已收到的动作，但没有隐藏的 Pixi 画布。只有当前团队加载和渲染场景。
- `OfficeDemoSource` 是明确启用的可选演示命令源。真实数据模式不提供演示按钮，不产生虚构的业务进度。
- 同一个办公室应用使用一条固定工作区 SSE，按 teamId 在本地路由到各自运行时；不再硬编码 office-1。新增团队不重连，也不重建其他团队会话或队列。独立场景仍可使用按 teamId 订阅的通用适配器。
- 场景投递只负责尽力展示，不逐条回报动画接收/开始/完成，不上传全量状态。断线不取消已接收的本地活动；业务操作响应和聊天终态仍有各自语义。
- Fastify 保存最新业务快照、连接表及有界的等待中 HTTP 请求，不保存离线动画队列。离线快照返回 202 已缓存；SSE 重连补发完整最新状态及同步完成标记，恢复不重播交接动画。多个页面分别收到消息，无租约或页面独占。
- 业务初始化、任务快照、状态读取和限时菜单通过同一个 POST 对接；菜单原请求等待用户选择，不要求后端提供回调接口。聊天仍由独立适配器处理。详见[最小业务接入](../../integration/docs/office-integration.md)。

`useOfficeTeamHost` 管理会话订阅与动画时钟；`OfficeApp` 仅订阅当前会话并组合 UI 与场景。应用关闭时停止订阅和网络连接。浏览器关闭后不会在本地继续运行业务任务，长期业务应由后端负责。

独立使用 `OfficeApp` 时由组件管理自己的会话。多团队集成时，由父组件通过 `useOfficeTeamHost(sessions)` 统一托管全部会话，再把当前团队的 `session` 传给 `OfficeApp`；切换时不要销毁会话或重新创建数据源。

## 新增办公室

- `OfficeTeamWorkspace` 组合初始办公室列表与可选的 `createTeam(input)` 数据源回调。列表为空时，动画区域显示创建入口；已有办公室时，团队空间列表末尾显示加号卡片。只有数据源提供创建能力时才显示可操作入口。
- 首版创建表单只填写名称，使用现有标准六人工位布局和固定人物外观，不提供未实现的容量扩展或人物配置。
- `DemoOfficeDirectory` 实现本地示例创建，新增办公室拥有独立的业务数据源和运行时，任务初始为空。新增定义的 ID、名称存储在 `pixoffice:classic:demo-offices:v1`，刷新后恢复；这不是完整业务状态、聊天或决策历史的持久化。
- 多标签页创建使用浏览器 Web Locks 串行保存，并在锁内重新读取、校验、合并最新目录，避免旧页面覆盖新办公室。现有会话对象不重建；其他标签页新增的办公室在刷新后显示。本地持久化创建需要支持 Web Locks 的安全上下文（HTTPS 或 localhost），不支持时明确报错，不增加后端接口或连接租约。
- `OfficeTeamHost` 对会话集合增量更新，只启动新增或上次启动失败的会话，不停止或重启已正常运行的会话。动画时钟不会因列表追加而重建。
- 服务器模式由后端发送 `offices.initialize` 新增或更新办公室。已有运行时保留；完整快照、白板与 `seq` 缓存在 `pixoffice:connected-offices:v3`。Fastify 内存随服务重启清空，需要后端重新初始化；前端此时提示等待同步。未完成菜单不补播，超时不产生默认选择。
