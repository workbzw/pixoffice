# PixOffice Dimetric

独立轴测产品的预览入口，与现有办公室、教室、农场分别构建。

默认页面是协作办公室视觉样板：独立房间、五位员工工位、项目白板、任务气泡和巡回助手。画面采用固定视角的 2.5D 位图分层，并使用 2:1 地面投影。它不是可旋转的三维模型，也不是像素画风。

```sh
# 在仓库根目录执行
npm install
npm run dev:dimetric -- --host 127.0.0.1 --port 5180
npm run build:dimetric
```

构建产物为本目录的 `dist/`，可单独静态部署。`public/` 生成许可证和本产品的 `studio/` 资源，不复制经典办公室、教室、农场或人物图集；构建检查会拒绝导入这些产品的场景、素材及旧页面。

## 协作办公室样板

- 点击工位、名牌、头像或任务气泡，查看成员任务。
- 项目、任务、成员、资料库和数据看板均有可操作的内容。
- 在任务中确认数据口径，解除周理的等待状态。
- 助手通过现有运行时寻路，依次到访五个工位。暂停、继续和重置同步作用于演示状态与移动。
- 报告可预览、下载为 TXT，明确标注为本地演示数据。
- 画布完整适配窗口，支持窄屏菜单与可读的详情弹窗。

当前边界：五个员工是完整的坐姿工位素材，不包含人物起身、行走、入座和敲键盘帧动画。巡回助手使用四方向素材与轻微悬浮运动。尚未接真实智能体或后端；本轮没有定义新的对外协议。

`src/studio/engine.ts` 管理本地演示状态并调用现有运行时；`geometry.ts` 管理地面投影；`controller/useStudioController.ts` 持有场景生命周期；`scene/` 负责位图分层和场景内容；`ui/StudioShell.tsx` 负责外层界面；`StudioApp.tsx` 负责装配。加 `?layout=scene` 可只显示场景，或通过 `shell` 属性换用另一套界面，详见[装配说明](../../docs/architecture/scene-and-shell.md)。当前资产是视觉样板，不作为正式可复用角色包发布。

源素材保存在 [`art/studio-v1/`](art/studio-v1/README.md)，包含生成提示词和来源记录。构建仅进行 WebP 编码，不手工修改人物或拼接肢体。

## 架构实验室

打开 `/?view=lab` 或左侧的「轴测实验室」链接，仍可进入先前的独立架构验证入口：

- 点击空地，屏幕位置反投影到整数格，再由共享运行时寻路。
- 入座、工作、离座、停止，以及障碍物避让与资源占用。
- 地面方向映射到四个斜向视图，步频按地面行程采样。
- 网格预览、不同窗口比例的完整画面适配。
- `dimetric-lab` 独立存档命名空间，不覆盖旧场景数据。

`src/scene.ts` 是规则，`src/assembly.ts` 是投影/视图装配，`src/appearance.ts` 是诊断标记适配器。标记和方块只用于检查契约，不是最终像素人物、家具或骨骼播放器。新素材应使用独立的 `presentationProfileId`，不能直接沿用旧素材假装完成轴测化。

正式制作轴测场景时，将稳定的规则和表现移入新的 `scene-dimetric-*` 包，将素材绑定移入 `assets-dimetric-*` 包；本目录保留应用装配。[双产品架构](../../docs/architecture/dual-products.md)说明开发边界和兼容策略。
